## Why

EquipED evaluates Student Learning Materials (SLMs) against Curriculum Instruction Development (CID) evaluation forms across Subject Matter Expert (SME), Program Coordinator, Gender and Development (GAD), and Information Technology Standards and Outcomes (ITSO) domains. Currently, rubric definitions are partially static, coupled to fixed code registries, and queried directly by worker threads during evaluation execution. Furthermore, Program Coordinator evaluations implicitly inherit Subject Matter Expert scores through legacy reconciliation (`server/modules/agents/coordinator/reconciliation.py`) rather than operating against an independent evaluation form and result contract.

To support evolving institutional CID evaluation forms, administrators require the ability to author, edit, reorder, validate, publish, independently activate, retire, and roll back evaluation forms using safe, typed scoring strategies without arbitrary code execution. Concurrently, worker-side database queries and ungrounded fallbacks must be eliminated in favor of atomic, pre-dispatch snapshot resolution and validation on the orchestrator thread.

## What Changes

- **Reuse and Extend Existing Rubric Model**: Extend existing `rubric_sets`, `rubric_domains`, and `rubric_criteria` models with publication, retirement, audit, and adapter metadata. Form families are identified by existing `agent_id`.
- **Single Source of Truth for Publication Lifecycle**: Use existing `rubric_sets.status` with allowed values `draft | published | retired` enforced by a database CHECK constraint. Migrate existing `status='active'` rows to `published`. Added metadata includes `published_at`, `published_by`, `created_by`, `retired_at`, `retired_by` (nullable only for migration/system seed rows; normal admin operations require non-null actors), `adapter_key`, and `adapter_version`. At most one editable draft exists per agent, enforced by a partial unique index. Bulk reordering is strictly ordering-only and retains every criterion under its existing domain without reparenting.
- **Shared Locking Protocol & Concurrency**: Enforce a strict shared locking protocol. Every draft child mutation, bulk reorder, and publication locks the parent `rubric_sets` row (`FOR UPDATE`) before checking status or modifying children. Activation, retirement, and combined publish+activate operations lock the agent's `rubric_agent_activations` row first, followed by all affected `rubric_sets` revision rows in deterministic `rubric_set_id` sort order, eliminating race conditions and deadlocks.
- **Retirement and Rollback Semantics**: Admins may retire non-active published revisions. Active revisions cannot be retired until another compatible revision is activated. Retired revisions cannot be activated, drafted from, or edited. Retirement affects future selection only; in-flight evaluations bound to immutable snapshots continue execution safely. Rollback is performed by activating an older still-published compatible revision.
- **Independent Atomic Activation**: Introduce `rubric_agent_activations(agent_id PK, rubric_set_id FK, updated_by, updated_at)` with composite foreign key enforcing same-agent targets, allowing each agent's active form revision to be activated independently. `updated_by` is nullable only for migration/system seed rows; every normal admin activation requires a non-null authenticated admin actor.
- **Two Explicit Paths for Evaluation Form Snapshots**: Introduce `evaluation_form_snapshots` with `UNIQUE(evaluation_id, agent_id)` and link future `AgentResult` records to `form_snapshot_id`. Snapshot creation supports two explicit paths: normal evaluations resolve current active revisions atomically on the orchestrator thread while transitioning into `EVALUATING`; Model Validation benchmark submission verifies echoed active published revisions under locks and atomically precreates the same standard `evaluation_form_snapshots` alongside the `EvaluationJob` and benchmark rows. Evaluation preparation and recovery reuse these precreated snapshots and never reread activations. Incomplete, partial, duplicate, or hash-mismatched snapshot sets fail closed.
- **Deterministic Canonical Hash & Bounds**: Snapshots enforce a deterministic UTF-8 canonical JSON SHA-256 hash across `evaluation_id`, `agent_id`, `rubric_set_id`/revision identity, `adapter_key`, `adapter_version`, ordered domains/criteria, presentation fields, and strategy key/config with sorted keys. Duplicated snapshot columns (`evaluation_id`, `agent_id`, `rubric_set_id`, `adapter_key`, `adapter_version`, `snapshot_hash`) must strictly equal their canonical hashed payload values at creation, dispatch, retry/recovery, and AgentResult persistence. Strategy configs strictly bound nesting depth, array lengths, string lengths, total serialized size per config/request/revision/snapshot, and finite numbers. Verified at draft save, locked publication, activation, creation, dispatch, recovery, and persistence.
- **Complete Elimination of Worker DB Access**: Pass recursively immutable frozen DTOs into worker threads for SME, Coordinator, GAD, and ITSO without ORM sessions or `_thaw`; eliminate all worker-side database lookups and fallbacks.
- **Coordinator Teardown and Independent Contract**: Decouple Coordinator from SME scores. Delete `server/modules/agents/coordinator/reconciliation.py` and remove `EvaluationOrchestrator._reconcile_coordinator_result`. Preserve existing Coordinator Version 1 (ten unexecuted rows) as retired legacy metadata; create and activate a new published Coordinator Revision 2 containing only the currently executable A-05 curriculum-alignment criterion. Synthesis calculates Coordinator contribution directly from its returned criterion count/form without altering agent-level synthesis weights.
- **Bounded Typed Scoring Strategies**: Support a registered set of typed strategies: `llm_rubric_guidance` (bounded validated LLM-assigned 1–4 score with prompt templates structurally delimiting untrusted document text), `count_band` (deterministic count band), `ratio_band` (deterministic ratio band), and `curriculum_alignment` (Coordinator-only). Unknown fields, provider/model/tool controls, and dynamic code are strictly forbidden. Monotonic non-overlapping bands cover exactly institutional scores 1–4.
- **Explicit Migration Strategy Backfill & Legacy Marker**: Forward migration maps current executable truth to valid strategy configurations across SME, GAD, ITSO, and Coordinator, and introduces `evaluation_jobs.is_pre_snapshot_legacy BOOLEAN NOT NULL DEFAULT FALSE` backfilling `TRUE` only for coherent historical evaluations with persisted `AgentResult` rows, zero snapshots, and all NULL `form_snapshot_id` values. Seed/bootstrap scripts stop destructive overwrites of admin revisions.
- **Migration Downgrade & Execution Safety**: Every schema/data change is a new forward migration. Migration downgrade is unconditionally irreversible and refuses to drop applied structures; deployed rollback requires a future forward compensating migration. Shared Neon execution requires an explicit manual approval checkpoint.
- **Faculty API and Authorization Boundary**: All evaluation responses remain authenticated and owner-scoped using existing masked ownership checks. A single allowlisted presentation DTO returns snapshot/form identity (`form_snapshot_id`, `rubric_set_id`, `version`), revision/hash/adapter identity (`snapshot_hash`, `adapter_key`, `adapter_version`), ordered domain/criterion definitions (UUID, code, title, description, order), and scorecard presentation fields (score, justification, evidence, ungrounded flags), while strictly excluding internal strategy configurations, scoring rules/guidance, raw prompt/response data, and unrestricted provenance. Full snapshot configurations are accessible only through admin-authorized endpoints.
- **Model Validation Exact Binding**: Benchmark preparation catalog returns exact active `rubric_set_id`, version, and rubric criterion UUID/code/title/domain/order. Benchmark submission echoes `rubric_set_id` and rubric criterion UUIDs with expected scores (1–4). Under activation-first/revision locks, submission verifies echoed revisions are currently active published compatible revisions with exact criterion UUID sets, creates the EvaluationJob, and persists standard `evaluation_form_snapshots` in the same transaction. Evaluation preparation and recovery reuse these precreated snapshots without altering benchmark criteria even if forms are later activated or retired. Supports partial validation (SME, GAD, ITSO, no curriculum) and full validation (SME, GAD, ITSO, Coordinator, with explicit curriculum).
- **Honest Legacy Handling**: Historical evaluations with `is_pre_snapshot_legacy = TRUE` return `Legacy — form snapshot unavailable` in API/UI metadata without inventing or retroactively attaching dynamic versions. Mixed or new missing snapshot bindings fail closed.

## Capabilities

### New Capabilities
- `dynamic-cid-evaluation-forms`: Dynamic Curriculum Instruction Development (CID) evaluation form authoring, draft editing (at most one draft per agent), atomic reordering, shared row locking protocol, typed scoring strategies (`llm_rubric_guidance`, `count_band`, `ratio_band`, `curriculum_alignment`), agent adapter validation, immutable revision publishing, retirement, and independent per-agent atomic activation.

### Modified Capabilities
- `evaluations`: Require pre-dispatch atomic resolution and persistence of `evaluation_form_snapshots` on the orchestrator thread coordinated with `EVALUATING` transition, pass frozen DTOs to workers, eliminate worker DB queries and Coordinator reconciliation teardown, fail preparation before worker dispatch on invalid/missing/partial snapshots after full/partial determination, and present legacy evaluations honestly.
- `evaluation-data-persistence`: Persist per-agent form revision, canonical snapshot hash with `adapter_key` and `adapter_version`, link `AgentResult` to `form_snapshot_id`, enforce matching evaluation/agent identity and payload equality, and record criterion scores bound to snapshot criteria without leaking internal strategy configs to faculty endpoints.
- `model-validation`: Return and bind exact published `rubric_set_id` and criterion definitions for validation benchmarks, validate expected scores against bound snapshot criteria (supporting full and partial validation), and prevent active pointer mutations from corrupting in-flight validation.
- `sme-engine-scoring`: Consume pre-resolved in-memory SME form snapshots; evaluate criteria via configured `count_band`, `ratio_band`, or `llm_rubric_guidance` strategies; preserve Revision 1 default codes/bands without hardcoded future requirements; eliminate worker DB lookups.
- `coordinator-full-path-hardening`: Decouple Coordinator from SME scores; delete reconciliation module, evaluate curriculum alignment against the independent Coordinator form snapshot Revision 2, and remove legacy ten-criterion SME merge logic.
- `gad-grounded-scoring`: Parameterize combined grounded extraction from the ordered criteria in the pre-resolved GAD form snapshot (`count_band` for instance lists, `ratio_band` for female/male counts); remove broad `except Exception` fallback and worker DB lookups.
- `itso-scoring-consistency`: Assemble ITSO frozen context, criteria codes, and output validation schemas dynamically from the pre-resolved ITSO form snapshot without worker DB queries.

## Impact

- **Backend Architecture**: `server/modules/rubrics` extended with draft lifecycle, shared row locking protocol, `rubric_agent_activations`, `evaluation_form_snapshots`, typed strategy engines, and adapter validators. Coordinator reconciliation module `server/modules/agents/coordinator/reconciliation.py` deleted.
- **Database**: Forward migration adding `rubric_agent_activations`, `evaluation_form_snapshots`, `agent_results.form_snapshot_id`, status CHECK constraint, partial unique draft index, composite FKs, and publication/retirement/audit columns on `rubric_sets` and `rubric_criteria`. Seeds SME, GAD, and ITSO Revision 1 as published and activated with backfilled strategies; seeds Coordinator Revision 1 as retired and Coordinator Revision 2 as published and activated. Downgrade is unconditionally irreversible.
- **Evaluation Pipeline**: Evaluator supervisor resolves, hashes, and persists all active agent snapshots in a single transaction before dispatch. Workers receive recursively immutable in-memory DTOs.
- **API & UI**: `/api/v1/admin/rubrics` and `client/src/features/admin/rubric-editor` updated with draft management, bulk reorder, validation, retirement, and activation controls. Authenticated owner-scoped faculty evaluation endpoints serve allowlisted presentation DTOs.
